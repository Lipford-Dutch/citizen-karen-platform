# Security Policy & Vulnerability Disclosure — Karing USA

## 🔒 Our Commitment

We take security, privacy, and user trust seriously. We commit to:  
- Protecting user data and PII at all times  
- Responding swiftly to vulnerability reports  
- Transparently disclosing security issues (when permitted)  
- Continuously improving security posture  

---

## 🛠️ What to Report

Please report (confidentially) any:  
- API vulnerabilities (injection, access control, broken auth)  
- Data leaks or exposure of sensitive user data  
- Misconfigurations (secrets exposed, TLS mis‑setup, permissions)  
- Vulnerabilities in third‑party dependencies  
- Abuse vectors (spam, automated abuse, brute force)  
- Anything that might compromise system integrity  

---

## 📬 How to Report

Send an email to: **security@karingusa.com** (or a secure alias) with:  
- Clear description  
- Steps to reproduce (if applicable)  
- Proof‑of‑concept (ideally minimal)  
- Optional contact info (you may remain anonymous)  

**Do NOT** publicly post vulnerabilities until disclosed or fixed.

---

## 📅 Response Timeline

| Stage | Commitment |
|-------|------------|
| Acknowledgment | Within **48 hours** |
| Initial Triage & Severity Assessment | Within **5 business days** |
| Patch / Mitigation Plan (if needed) | Within **30 days** for high‑severity issues |
| Public Disclosure or Report Closure | Within **60 days** after fix or per agreement |

---

## 🔄 Dependency & Supply Chain Security

- We use automated tools (`pip-audit`, `npm audit`, lock‑files)  
- Security updates are prioritized and deployed immediately  
- All dependencies are reviewed for licensing, vulnerabilities, maintenance status  

---

## 📁 Responsible Disclosure / Bug Bounty

At this stage, we do not run a formal bounty program — but we commit to crediting responsible reporters (if they consent), and working to remediate issues swiftly.

---

Thank you for helping keep Karing USA safe and trustworthy.
